Выполни полный цикл выпуска дайджеста по теме тахографов и грузоперевозок.
Строго соблюдай правила проекта:

- редполитика и формат — [.claude/rules/article-style.md](../../rules/article-style.md);
- git-процесс — [.claude/rules/git-workflow.md](../../rules/git-workflow.md).

Выполняй шаги строго по порядку. Дату бери текущую (не хардкодь).

## Шаг 1. Поиск новостей

Через MCP-сервер **Tavily** найди свежие новости (за последнюю неделю) по тематике проекта:
тахографы, карты тахографа, режим труда и отдыха, БДД, изменения законодательства
и штрафы, практика грузоперевозок.

- Запросы формулируй по-русски, например: «тахографы новости», «режим труда и отдыха
  водителей изменения», «штрафы тахограф», «электронные перевозочные документы».
- Отбирай по критериям из article-style.md: актуальность, практическая ценность,
  влияние на водителей/перевозчиков, достоверный источник.
- Отбери **3–5** новостей для одного выпуска. У каждой сохрани ссылку на источник.

Если свежих релевантных новостей меньше трёх — остановись и сообщи об этом,
не выдумывай инфоповоды.

## Шаг 2. Написание дайджеста

Напиши дайджест строго по формату из article-style.md:

- **Один файл**: `src/content/blog/YYYY-MM-DD-digest.md` (дата — текущая).
  Если файл с такой датой уже есть — добавь суффикс, например `-2`.
- **Frontmatter** (по схеме `src/content/config.ts`):
  ```yaml
  ---
  title: "<заголовок выпуска>"
  description: "<1–2 предложения о содержании выпуска>"
  pubDate: "YYYY-MM-DD"
  tags: ["тахографы", ...]
  ---
  ```
- **Тело**: 3–5 новостей, на каждую — подзаголовок `##`, краткое объяснение и вывод,
  100–150 слов на новость. В конце каждой новости — ссылка на источник.
- **Стиль**: просто, по фактам, без маркетинга и лишней юридической сложности.
  Если есть сомнения в актуальности — прямо это указать.

Запомни итоговый **slug** файла (`YYYY-MM-DD-digest`) — он понадобится для обложки.

## Шаг 3. Генерация обложки

Собери на английском промпт в стиле modern, minimalist, tech-oriented illustration,
без текста на изображении, отражающий тему выпуска (тахографы/грузоперевозки).

Через MCP-сервер **Replicate** вызови модель `black-forest-labs/flux-schnell`
(`create_models_predictions`, `Prefer: wait`) с параметрами:

- `prompt`: составленный английский промпт;
- `num_outputs`: 1;
- `aspect_ratio`: "16:9".

Скачай результат (прямой URL из `output`) и сохрани **рядом со статьёй** как
`src/content/blog/<slug>.webp`. Это локальный ассет для Astro `image()`.

## Шаг 4. Подключение обложки

Добавь во frontmatter статьи поле `heroImage` со ссылкой на локальный файл:

```yaml
heroImage: "./<slug>.webp"
```

Путь относительный к markdown-файлу — так требует схема `heroImage: image()`.
Не используй URL из `public/` — по схеме это должен быть импортируемый ассет.

## Шаг 5. Сборка, коммит и публикация

Соблюдай git-workflow.md:

1. Создай/переключись на ветку `feature/digest-YYYY-MM-DD` (никогда не коммить в `main`).
2. Прогони проверки: `npm run build && npm run typecheck`. Если падают — почини
   и не коммить сломанное.
3. Добавь в индекс новые/изменённые файлы выпуска (`.md` и `.webp`).
4. Коммит русским conventional-commit со скобкой области:
   `content(digest): дайджест <тема> от YYYY-MM-DD — N новостей`.
5. Запушь ветку `feature/digest-YYYY-MM-DD` в remote (не в `main`).

## Шаг 6. Отчёт

Выведи сводку:

- заголовок выпуска и путь к файлу;
- количество новостей и их источники;
- путь к обложке;
- имя ветки и hash коммита;
- URL деплоя (если известен из Vercel).
